# Y-Gaming Personal Hub — Design Specification

**Version:** 0.2  
**Domain:** `y-gaming.in`  
**Design direction:** Dark / Minimal / Personal / Editorial  
**Primary identity:** Simon  
**Creator brand:** Y-Gaming

---

# 1. Design North Star

> **A quiet, dark, modern space that lets an interesting person be interesting.**

The site should feel like **Simon’s personal corner of the internet**, not a conventional portfolio.

The visual language should be:

- Minimal
- Clean
- Dark
- Modern
- Personal
- Slightly technical
- Creative without being chaotic

The site should become more interesting as the visitor explores it.

---

# 2. Visual Direction

We're intentionally positioning the site between:

**Personal website × Developer portfolio × Creator hub**

Rather than:

**Developer portfolio × Gaming website**

Gaming is part of Simon's personality, but the visual design shouldn't scream *gaming*.

### Avoid

- Neon cyberpunk aesthetics
- Excessive gradients
- Excessive glassmorphism
- Giant glowing elements
- Particle backgrounds
- Overly animated interfaces
- Excessive rounded cards
- Generic AI-generated portfolio layouts

### Prefer

- Strong typography
- Large areas of negative space
- Editorial layouts
- Asymmetric compositions
- Restrained color usage
- High-quality imagery
- Subtle interaction
- Content-driven design

---

# 3. Color System

The supplied green palette becomes the foundation of the visual identity.

### Primary palette

| Role | Color |
|---|---|
| Sage | `#9CB080` |
| Muted Green | `#618764` |
| Deep Green | `#2B5748` |
| Green Charcoal | `#273338` |

### Dark UI palette

| Role | Starting value |
|---|---|
| Background | `#0D1110` |
| Surface | `#141A17` |
| Elevated Surface | `#1B2420` |
| Primary text | `#F1F3EF` |
| Secondary text | `#A8AEA8` |
| Muted text | `#737A74` |

Borders should generally use a very subtle translucent white/green rather than solid bright lines.

### Color philosophy

The green palette is an **accent**, not the background.

The website should primarily feel dark and neutral, with green appearing when something deserves attention.

The light sage:

**`#9CB080`**

will be the primary candidate for the site's recognizable accent.

Potential uses:

- Links
- Hover states
- Selected navigation
- Small highlights
- Metadata
- Buttons
- Decorative details
- Occasional typography emphasis

The deeper greens provide hierarchy without requiring additional accent colors.

---

# 4. Typography

### Primary typeface: Geist

Geist will be the initial typeface for the entire website.

It provides:

- Clean sans-serif forms
- Excellent readability
- Modern appearance
- Strong large-scale typography
- A subtle technical character

We will avoid introducing a separate decorative display font initially.

The personality should come from **scale, spacing and composition**, rather than unusual typography.

### Typography philosophy

The site should be comfortable reading at normal sizes but occasionally use **very large typography** as a visual element.

For example:

> **SIMON**

can occupy a significant portion of the hero without needing decorative treatment.

---

# 5. Hero / Homepage Opening

The hero is the **primary homepage experience**.

It should immediately establish Simon as the subject.

The first screen should feel spacious and quiet.

Conceptually:

SIMON

I like making things.

Community Manager · Creator · Builder

↓ Explore

This is a visual concept rather than final copy.

### Hero characteristics

- Large typography
- Significant negative space
- Dark background
- Minimal green accents
- No mandatory profile photo
- No résumé-style introduction
- No wall of text
- Subtle indication that content continues below

The hero should create curiosity rather than explain everything.

---

# 6. Homepage Flow

After the hero, the homepage should gradually reveal different aspects of Simon.

A potential progression:

Hero  
↓  
Who I am  
↓  
What I do  
↓  
What I build  
↓  
What I'm exploring  
↓  
What I enjoy  
↓  
Y-Gaming  
↓  
Connect

The exact layout will be designed visually rather than implemented as a rigid sequence of identical sections.

---

# 7. Editorial Layout

The site should avoid relying primarily on uniform card grids.

Instead, sections should use varying visual weights.

For example:

### Featured project

ValorantRank.Chat can occupy a large portion of the viewport.

### Secondary projects

Smaller projects can appear around it.

### Artwork

Artwork can use an asymmetric gallery.

### Interests

Interests can use typography, imagery or smaller visual modules rather than identical cards.

The layout should feel **editorial and curated**.

---

# 8. Navigation

Navigation should remain minimal.

Potential structure:

SIMON                         WORK
                              BUILD
                              CREATE
                              EXPLORE
                              CONNECT

The exact labels remain open.

The important principle is:

> **Few destinations, clear meaning.**

We should avoid exposing every possible page in the primary navigation.

### Desktop

A persistent or easily accessible minimal navigation.

### Mobile

A compact navigation that expands when requested.

No complicated mega-menu.

---

Professional information should be visually polished but shouldn't dominate the website.

Potential content:

- BlueStacks
- BotLabs
- Community Management
- Carl-bot
- YAGPDB
- Discord ecosystem
- Other professional work

The presentation should emphasize **what Simon actually does**, rather than simply listing job titles.

# 10. Build / Projects

This is where Simon's creator/builder side becomes prominent.

Potential projects:

- ValorantRank.Chat
- Discord bots
- Websites
- Tools
- Other experiments

# 12. Current / Exploring

This section represents Simon's current curiosity.

Initial example:

### Currently exploring

**3D Printing**

> Learning how to turn digital ideas into physical things.

The content should be easy to replace as interests change.

This is intentionally different from a permanent "skills" section.

# 13. Interests

Interests should communicate personality rather than function as a checklist.

Potential interests:

- Gaming
- Anime
- Music / K-pop
- Movies
- Books
- Art
- Other hobbies

Instead of presenting them as simple category names, we should explore ways to make them feel like **windows into Simon's life**.

This could eventually include current/favorite items rather than merely category names.

---

# 14. Y-Gaming

Y-Gaming should have a distinct presence because it represents Simon's **gaming and content brand**.

It should clearly communicate:

> **Y-Gaming**  
> Simon's gaming & content brand.

Potential content:

- YouTube
- Streaming
- Gaming content
- Creator activities
- Related social channels

The visual language can become slightly more energetic here while remaining part of the site's overall design system.

Y-Gaming should **not** visually take over the entire website.

---

# 15. Artwork

Artwork should have its own visual treatment.

Rather than a standard project grid, we should explore:

- Editorial gallery
- Masonry-like arrangement
- Large featured artwork
- Full-screen image viewing
- Minimal metadata

The artwork itself should remain the focus.

---

# 16. Personal Signature

We are **not forcing a signature element yet**.

Instead, we will allow the identity to emerge from:

- Geist typography
- The green palette
- Large-scale typography
- Editorial composition
- Spacing
- Potential Y-Gaming-derived visual elements

If a distinctive motif emerges naturally during prototyping, we can adopt it.

The rule is:

> **No gimmick unless it makes the design better.**

---

# 17. Motion

Motion remains subtle.

### Appropriate

- Smooth hover states
- Small image reveals
- Page transitions
- Section entrance animations
- Navigation transitions
- Underline animations
- Slight transforms on interactive elements

### Avoid

- Constant movement
- Parallax everywhere
- Particle systems
- Cursor trails
- Long animations
- Animated backgrounds
- Motion that delays interaction

All motion must respect:

`prefers-reduced-motion`

---

# 18. Responsive Design

The design should be created with mobile in mind from the beginning.

### Desktop

Take advantage of:

- Large typography
- Wide whitespace
- Editorial compositions
- Asymmetric layouts

### Mobile

Prioritize:

- Reading flow
- Touch targets
- Clear hierarchy
- Appropriate typography scaling
- Image quality
- Simple navigation

The mobile site should feel intentionally designed rather than being a collapsed desktop layout.

---

# 20. Content Architecture

Content should remain separate from presentation where practical.

Potential structure:

```text
data/
├── profile
├── work
├── projects
├── interests
├── artwork
├── socials
├── creator
└── current
```

For example, changing a social account should involve changing data, not redesigning a page.

This will also make the project significantly easier for Cursor agents to maintain.

---

# 21. Accessibility

Required from the beginning:

- Semantic HTML
- Keyboard navigation
- Visible focus states
- Sufficient color contrast
- Alt text
- Logical heading hierarchy
- Reduced-motion support
- Appropriate touch targets
- No interaction that depends solely on hover

Accessibility is part of development and QA, not a final cleanup task.

---

# 22. SEO / Sharing

The site should include:

- Meaningful page titles
- Meta descriptions
- Open Graph metadata
- Social sharing images
- Favicon
- Canonical URLs where appropriate
- Semantic page structure

`y-gaming.in` should produce a polished preview when shared.

Individual project pages should eventually have their own metadata.

---

# 23. Design Rules for Cursor

These will eventually become part of the project's persistent AI instructions.

### Do

- Use whitespace deliberately
- Maintain strong typography hierarchy
- Reuse established components
- Preserve the green palette
- Keep the interface restrained
- Optimize images
- Design mobile and desktop together
- Maintain accessibility
- Prefer semantic HTML
- Keep content and presentation separated

### Don't

- Add random gradients
- Add neon gaming aesthetics
- Overuse glassmorphism
- Turn everything into cards
- Add unnecessary animations
- Introduce colors without justification
- Use excessive rounded containers
- Fill whitespace simply because it exists
- Create a generic AI portfolio aesthetic
- Make visual changes that conflict with the established system
